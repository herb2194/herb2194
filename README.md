# 안녕하세요, 신입 풀스택 개발자 문예지입니다 👋

서비스의 화면과 기능 흐름을 구현하는 개발자를 목표로 하고 있습니다.  
사용자가 실제로 서비스를 이용하는 흐름을 기준으로 화면을 설계하고, 그 행동이 안정적으로 처리될 수 있도록 프론트엔드와 백엔드를 함께 연결하는 데 관심이 있습니다.

Spring Boot와 React를 중심으로 웹 서비스를 개발했으며, 팀 프로젝트에서는 실시간 라이브 스트리밍, 채팅, 결제, 알림 기능을 담당했고, 개인 프로젝트에서는 패션 커머스 플랫폼의 주요 기능을 기획부터 구현까지 진행했습니다.

### 🔍 Troubleshooting

| 문제 | 원인 | 해결 |
|---|---|---|
| 다중 시청자 라이브 연결 오류 | Viewer가 먼저 입장한 경우 Host 입장 시 기존 Viewer에 대한 연결 트리거가 부족해 offer/answer 협상이 시작되지 않음 | signaling payload에 socket 식별값을 추가하고, Host와 Viewer 간 signaling 흐름을 정리하여 연결 구조를 개선 |
| 실시간 기능 간 이벤트 충돌 | 라이브 채팅, 1:1 채팅, WebRTC signaling이 동시에 동작하면서 이벤트 범위가 혼동될 가능성이 있었음 | live와 direct chat의 socket 흐름을 분리하고, room 단위 이벤트 처리 기준을 명확히 설정 |
| 결제 / 포인트 / 알림 연동 순서 관리 | 결제 성공, 예약 상태 변경, 포인트 적립, 알림 발송이 서로 연결되어 있어 처리 순서가 중요했음 | 결제 완료 이후 상태 변경, 포인트 적립, 알림 발송이 순차적으로 이어지도록 서비스 흐름을 분리하여 구성 |
